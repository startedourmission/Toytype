# Toytype

Toytype은 웹페이지와 Google Docs 원고에서 오탈자 후보를 찾는 Chrome 확장 프로그램입니다.
내장 `rules.json`으로 결정론 검사를 수행하고, Google Docs에서는 문서 위치 선택, 항목별 적용, 로컬 용어 통일 표, HWPX 내보내기, 이미지 추출, 목차 추출, 단락 스타일 셋팅을 제공합니다. 로컬 브리지/외부 CLI가 필요한 AI 보조 검토, AI 사실 검증, AI 문장 길이 조절은 기본 비활성화되어 있으며 옵션에서 켤 수 있습니다.

- 현재 버전: `1.0.0`
- 내장 규칙: 8개 카테고리, 6,866개 규칙
- 기본 검사만으로는 문서를 수정하지 않습니다.
- Google Docs에서 사용자가 항목별 [적용] 버튼을 누른 경우에만 해당 선택 영역 교체를 시도합니다.

## 설치

1. Chrome 주소창에서 `chrome://extensions`로 이동합니다.
2. 우측 상단 [개발자 모드]를 켭니다.
3. [압축해제된 확장 프로그램을 로드]를 누르고 이 폴더(`Toytype`)를 선택합니다.
4. 툴바 확장 아이콘에서 Toytype을 확인합니다.

로컬 HTML 파일(`file://`)도 검사하려면 확장 세부정보에서 [파일 URL에 대한 액세스 허용]을 켜세요.

## 기본 사용

### 일반 웹페이지

- 발견된 위치에 물결 밑줄과 배경색을 표시합니다. DOM을 바꾸지 않고 CSS Custom Highlight API로만 그리므로 페이지 구조를 건드리지 않습니다.
- 밑줄 표시는 툴바 팝업의 [본문에 빨간 밑줄 표시]나 설정 페이지에서 끌 수 있습니다. 꺼도 검사와 배지 숫자는 유지됩니다.
- 툴바 배지는 현재 탭의 발견 건수를 보여줍니다.
- 카테고리별 검사 범위와 사이트별 비활성화는 설정 페이지에서 지정합니다.

색상 계열:

| 색 | 카테고리 |
|---|---|
| 빨강 | 표기 변환, 맞춤법, 맨마지막 |
| 보라 | 존대와 복수, 높임말 서술어 |
| 주황 | 공백 1, 공백 2, 공백 3 |

### 툴바 아이콘 팝업

- [오탈자]: 현재 탭의 발견 건수를 보여줍니다. 기본은 접힘이고, 누르면 카테고리별 목록이 펼쳐집니다. 항목을 클릭하면 교정어가 클립보드에 복사됩니다. [다시 검사]로 재검사합니다.
- [본문에 빨간 밑줄 표시]: 일반 웹페이지 본문의 물결 밑줄을 켜고 끕니다. 끄면 밑줄만 감추고 검사·목록·툴바 배지 숫자는 그대로 유지합니다. Google Docs 탭에서는 원래 밑줄을 긋지 않으므로 이 항목이 표시되지 않습니다.
- [브릿지 · AI 기능 사용]: 외부 기능 스위치. 끄면 아래 항목이 모두 숨겨집니다.
- [로컬 브리지]: 연결 상태 배지. 팝업을 열면 브리지가 꺼져 있어도 자동으로 켭니다. 연결되면 [다시 확인]과 [상주 끄기], 아직이면 [연결] 버튼을 보여줍니다.
- [AI 엔진]: 접힌 상태에서는 현재 엔진 이름만 보여주고, 펼치면 Codex · Claude Code · Grok 중에서 고를 수 있습니다. 각각 [테스트]로 연결을 확인하며, 브리지가 CLI 설치 여부(설치됨/없음)도 함께 보여줍니다.

AI 기능 실행(AI 교정 생성, AI 사실 검증, AI 문장 길이 조절, 용어 통일 표)은 Google Docs 패널의 [추가기능]과 [용어 통일 표] 버튼이 담당합니다. 팝업에는 중복해서 두지 않습니다.

### Google Docs

Google Docs에서는 본문에 밑줄을 긋지 않고, 우하단 패널 목록으로만 표시합니다.

- [버블]: Toytype 패널 열기
- [항목]: 문서 위치 선택 + 교정어 복사
- [적용]: 선택 영역을 교정어로 교체 시도
- [x]: 현재 문서에서만 해당 항목 숨김
- [다시 검사]: 현재 문서 모델 기준으로 재검사
- [JSON 업로드]: `rules.json` 구조의 파일을 임시 규칙으로 적용
- [종류별/문서 순서 보기]: 카테고리 묶음 또는 문서 등장 순서로 전환
- [문서 순서 보기]에서는 커서 위치를 표시하고 목록 스크롤이 커서 주변 항목을 따라갑니다.
- [설정]: 동작 모드와 부가 설정 열기
- [용어 통일 표]: 본문에서 혼용된 용어를 로컬 사전과 `garu-ko` 형태소 분석으로 표로 분석
- [추가기능]: 기본 모드에서는 HWPX 내보내기, 이미지 추출, 목차 추출, 단락 스타일 셋팅을 표시합니다. 옵션에서 브릿지/외부 기능을 켜면 AI 교정 생성, AI 사실 검증, AI 문장 길이 조절도 표시합니다.
- 브리지 배지: 브릿지/외부 기능을 켰을 때만 표시합니다. 초록 점이면 연결됨, [꺼짐]이면 미연결입니다. [꺼짐]을 누르면 재시작 명령을 복사합니다.

내부 Google Docs 문서 모델 접근이 막히면 텍스트 export로 fallback합니다.

## AI 교정 생성

AI 교정은 선택 기능입니다. 기본값은 꺼짐입니다. Chrome 확장은 로컬 CLI를 직접 실행할 수 없으므로 로컬 브리지가 Codex, Claude Code, Grok 중 선택한 CLI를 대신 실행합니다.

### 최초 1회 설치

터미널에서 딱 한 번만 실행합니다.

```bash
npm run setup
```

이 명령은 Chrome 네이티브 메시징 호스트를 등록합니다. 확장이 로컬 프로세스를 직접 띄울 수 없기 때문에, 이 호스트가 대신 브리지를 실행해 주는 역할을 합니다.

`npm run setup`은 저장소를 어디에 두든 그 위치를 스스로 찾아 등록합니다. 브리지도 자기가 놓인 폴더를 작업 폴더로 씁니다. 다른 경로를 쓰려면 설정 페이지의 [작업 폴더]에 직접 적으세요.

### 다른 사람에게 배포할 때

AI 기능까지 쓰게 하려면 받는 쪽에 다음이 필요합니다.

- **Node.js** — 브리지와 설치 스크립트가 node로 동작합니다.
- **AI CLI 중 하나** — `codex`, `claude`, `grok` 중 하나가 설치되어 있고 로그인된 상태여야 합니다. 각각 별도 구독이 필요합니다. Toytype은 CLI를 대신 실행할 뿐 API 키를 대신 제공하지 않습니다.
- **`npm run setup` 1회 실행** — 이 단계만 터미널이 필요합니다.

확장 ID는 `manifest.json`의 `key` 필드로 고정되어 있습니다. 같은 빌드를 받아 로드하면 누구 컴퓨터에서든 ID가 같아지므로, 네이티브 호스트 등록이 그대로 동작합니다. `key`를 지우거나 바꾸면 ID가 달라져 팝업의 [연결]이 실패합니다.

AI 기능 없이 오탈자 검사만 쓸 사람은 아무 설치도 필요하지 않습니다. 확장만 로드하면 됩니다.

### 이후 사용

툴바 아이콘을 누르면 팝업이 열리면서 브리지가 자동으로 켜집니다. 터미널을 열 필요가 없습니다.

- 브리지는 `~/Library/LaunchAgents/com.toytype.aibridge.plist`로 등록되어 로그인할 때마다 자동 실행됩니다.
- 죽으면 launchd가 다시 살립니다(`KeepAlive`).
- 로그는 `~/.toytype/logs/bridge.log`에 쌓입니다.
- 상주를 끄려면 팝업의 [상주 끄기]를 누릅니다. 설치 자체를 되돌리려면 `npm run setup:remove`를 실행합니다.

### 수동 실행 (선택)

브리지를 직접 띄우고 싶을 때만 씁니다.

```bash
node tools/toytype_ai_bridge.mjs --port 17644
```

위 명령은 foreground 서버라서 실행 후 터미널을 계속 잡고 있습니다. AI 기능을 쓰는 동안 그 터미널을 열어 두고, 중지하려면 [Ctrl-C]를 누릅니다.

브리지를 재시작하려면 다른 터미널에서 다음 명령을 실행합니다.

```bash
node tools/toytype_ai_bridge_ctl.mjs restart --port 17644
```

이 재시작 명령은 백그라운드로 브리지를 띄우고 바로 종료됩니다. 로그는 다음 명령으로 확인합니다.

```bash
tail -f /tmp/toytype-ai-bridge-17644.log
```

AI 교정 생성, AI 사실 검증, AI 문장 길이 조절은 브릿지/외부 기능을 켰을 때만 사용할 수 있습니다. AI 작업은 브리지 콘솔에 시작/완료/실패 로그를 남깁니다. 백그라운드로 실행한 경우 같은 내용이 위 로그 파일에 기록됩니다.

재시작 후에도 터미널을 서버로 잡아 두고 싶으면 다음처럼 실행합니다.

```bash
node tools/toytype_ai_bridge_ctl.mjs restart --port 17644 --foreground
```

브리지가 이미 실행 중이면 같은 명령을 한 번 더 실행할 필요가 없습니다. `EADDRINUSE` 또는 “already running” 메시지가 나오면 기존 브리지가 포트를 사용 중이라는 뜻입니다.

브리지 상태와 오류 확인:

- Google Docs 패널 좌하단의 작은 초록 점은 브리지 연결 상태만 표시합니다. 정상 연결이면 별도 텍스트를 붙이지 않고, 끊겼을 때만 [꺼짐]을 표시합니다.
- AI 교정 생성, 용어 통일 표, AI 사실 검증, AI 문장 길이 조절은 확장 background를 오래 붙잡지 않고 Google Docs 탭에서 로컬 브리지로 직접 요청합니다.
- 콘솔에 `extension_message_failed`가 보이면 브리지가 실제로 꺼진 것이 아니라 확장 background 응답 채널이 끊긴 상황일 수 있습니다. 이때는 Chrome 확장 페이지에서 [새로고침]을 누른 뒤 Google Docs 탭도 새로고침합니다.
- `filesystem:https://docs.google.com/...woff2` 폰트 오류나 Google Apps Script Rhino 경고는 Toytype 브리지 연결과 무관합니다.

설정 페이지에서 지정할 수 있는 항목:

- 브리지 URL: 기본 `http://127.0.0.1:17644`
- 브릿지/외부 기능 사용: 기본 꺼짐
- AI 엔진: Codex, Claude Code, Grok
- 요청 제한 시간: 기본 `1800000ms`(30분)
- Codex/Claude/Grok 명령 경로
- 작업 폴더
- 생성 JSON 저장 폴더
- 오래된 생성 JSON 제거 기준: 1일, 7일, 30일, 60일, 180일
- 요청 제한 시간과 문서 최대 전달 길이
- 목차 추출 최대 깊이
- 항목 선택 시 자동 복사 여부

AI 교정 생성 방식:

1. Google Docs 본문 텍스트를 읽습니다.
2. 별도 fact-check 패스를 먼저 실행합니다. Codex 사용 시 `gpt-5.5`, Claude Code 사용 시 Sonnet을 사용하고, Claude 경로에서는 `WebFetch`/`WebSearch` 도구를 허용합니다.
3. 내장 `rules.json`과 fact-check 보고서를 참고 자료로 함께 전달합니다.
4. AI는 단순 맞춤법보다 비문, 윤문, 내용 오류, 내용 중복, 문서별 용어 일관성을 우선 검토합니다.
5. 결과를 Toytype JSON으로 저장하고, 현재 문서 검사 규칙으로 자동 적용합니다.
6. 같은 문서 id의 generated JSON은 규칙 드롭다운에 표시됩니다.
7. `book-editing-technical` 또는 `기술 및 내용 정확성` 항목은 목록에서 제안어 아래에 해설도 함께 표시합니다.

생성 파일명:

```text
<google-docs-id>-<timestamp>.json
```

패널 드롭다운에는 문서 id 대신 `ai 검토-<timestamp>.json`으로 표시됩니다.
같은 AI 검토 결과는 생성 JSON 한 항목으로만 드롭다운에 표시합니다.

AI 작업 중에는 패널 푸터에 진행 상태와 경과 시간이 고정 표시됩니다. 완료/실패 상태도 사라지지 않고 마지막 결과로 남습니다.

## 용어 통일 표

Google Docs 패널 푸터에서 [설정]과 [문장 제안] 사이의 [용어 통일 표] 아이콘을 누르면 현재 본문을 로컬 분석기가 읽고, 같은 권장 표기에 속한 용어가 서로 다른 표면형으로 쓰인 경우와 영문/약어 뒤 조사 오류 후보를 표로 보여줍니다.

- 문서에는 아무것도 적용하지 않습니다.
- 패널을 열면 현재 문서의 용어 분석을 1회 자동으로 미리 실행합니다. 로컬 브리지가 꺼져 있어도 동작합니다.
- [재분석]은 브라우저 확장 안에서 새 로컬 분석을 다시 실행합니다.
- 결과는 패널 안 표로만 표시하며, 문장 제안 JSON이나 브리지 출력 파일로 저장하지 않습니다.
- 분석은 `rules.json`의 표기 변환 규칙에서 명사·외래어성 용어 변형군을 만들고, 내장 vendored `garu-ko`로 본문 명사와 외래어 토큰을 추려 후보를 좁힌 뒤 표면형 등장 횟수를 셉니다. 조사 오류 후보는 garu가 영문/약어+조사 어절로 분석한 경우에만 약어 읽기 기준으로 검사합니다. 별도 npm 설치는 필요하지 않습니다.
- 표에는 혼용 표기나 조사 오류 표기, 횟수, 권장 표기, 근거를 표시합니다.

## AI 사실 검증

Google Docs에서 문장을 드래그한 뒤 [추가기능] ➝ [AI 사실 검증]을 누르면 선택한 부분의 사실 주장을 검증해 패널 안 표로 보여줍니다.

- 문서에는 아무것도 적용하지 않습니다. 결과는 표로만 보여주고 저장하지 않습니다.
- 전체 원고 대신 선택 원문과 앞뒤 1,200자 문맥만 로컬 브리지에 전달합니다.
- 날짜, 인명, 기관명, 통계, URL, 제품 동작, 법률·기술 주장 같은 구체적 사실을 검증합니다. 문체 교정은 하지 않습니다.
- **웹 검증은 Codex 엔진에서 가장 안정적으로 동작합니다.** 실측 결과 Codex는 `webAccess: used`로 모든 항목에 근거 URL을 붙였습니다.
- Claude Code는 `--tools`와 별개로 `--allowedTools`가 있어야 웹 도구를 실제로 쓸 수 있습니다. 이 플래그가 빠지면 "I don't have permission to use WebSearch"라며 근거 없이 답합니다.
- Grok은 이 프롬프트에서 웹 검색 도구 호출이 취소(`stopReason: cancelled`)되어 JSON을 반환하지 못하는 문제가 있습니다. 사실 검증에는 Codex를 쓰세요.
- 근거 URL은 표에 링크로 표시됩니다. 근거가 하나도 없으면 브리지가 웹 접근을 `unavailable`로 낮춰 표시합니다.
- 판정은 네 가지입니다: 근거 있음, 사실과 다름, 확인 불가, 맥락 필요. 사실과 다른 항목이 표 위쪽으로 정렬됩니다.
- 웹 검색이 안 된 경우 표 위에 노란 경고를 띄우고, Codex로 바꾸라고 안내합니다. 그 판정은 검증이 아니라 모델의 기억이므로 신뢰하면 안 됩니다.
- 주장을 클릭하면 문서에서 해당 위치를 선택합니다. 교정문이 제안된 경우 클릭하면 클립보드에 복사됩니다.
- 확인 불가는 틀렸다는 뜻이 아니라 근거를 찾지 못했다는 뜻입니다. 최종 판단은 사람이 해야 합니다.

## AI 문장 길이 조절

Google Docs에서 문장을 드래그한 뒤 [추가기능] ➝ [AI 문장 길이 조절]을 누르면 현재 선택 영역의 글자 수와 함께 목표 글자 수를 입력하는 팝업이 뜹니다.

- 입력 범위는 1자부터 20,000자까지입니다.
- AI는 목표 글자 수를 기준으로 ±15자 안팎에 맞추되, 의미 보존과 자연스러움을 우선합니다.
- 선택 원문, 선택 앞뒤 문맥, 현재 글자 수, 목표 글자 수를 로컬 브리지에 전달합니다.
- AI 응답은 Toytype JSON 규칙으로 저장됩니다.
- 저장 파일명은 `<google-docs-id>-문장제안.json`이며, 실행할 때마다 규칙이 누적됩니다.

## 목차 추출

Google Docs 패널의 [추가기능] ➝ [목차 추출]은 AI를 사용하지 않습니다.

- Google Docs markdown export와 문서 개요 DOM을 우선 사용합니다.
- H1부터 H5까지 추출합니다.
- 결과는 자동으로 클립보드에 복사됩니다.
- 출력은 `#`, 제목, “추출:” 같은 부가 문구 없이 목차 줄만 생성합니다.
- H2부터는 `_`, H3는 `__`처럼 레벨에 맞춰 언더바를 붙입니다.

## HWPX 내보내기

Google Docs 패널의 [추가기능] ➝ [HWPX 내보내기]는 브릿지나 DOCX export를 사용하지 않고 Chrome 확장 안에서 바로 `.hwpx` 파일을 생성합니다.

- Google Docs HTML export를 읽어 HWPX ZIP/XML 패키지로 변환합니다.
- 제목 태그(H1~H4), 표, 이미지, 기본 굵게/기울임 서식을 보존합니다.
- Google Docs 수식은 HTML export에서 이미지로만 내려오므로, 수식이 있으면 DOCX export를 추가로 받아 그 안의 OMML을 한글 native 수식(`hp:equation`)으로 변환합니다. 변환에 실패한 수식만 이미지로 보존합니다.
- 표는 셀 주소, 병합(`rowspan`/`colspan`), 테두리 골격을 포함해 생성합니다.
- 문단마다 `linesegarray`를 생성하고, `rhwp`의 `LinesegArrayEmpty`/`LinesegUncomputed`/`LinesegTextRunReflow` 기준을 피하도록 긴 문단은 여러 lineseg로 나눕니다.
- `version.xml`, `settings.xml`, `Preview/PrvImage.png`, `META-INF/container.rdf`, `META-INF/manifest.xml` 등 한컴 호환 필수 패키지 엔트리를 함께 생성합니다.
- 다운로드 파일명은 현재 문서 제목 기반의 `<제목>.hwpx`입니다.
- 레거시 바이너리 `.hwp`가 아니라 한컴 2020+ 계열에서 여는 `.hwpx`입니다. 브라우저 단독 구현을 위해 HWPX를 우선 지원합니다.

## 이미지 추출

Google Docs 패널의 [추가기능] ➝ [이미지 추출]은 브릿지 없이 확장 안에서 동작합니다. 현재 문서를 DOCX로 export한 뒤 문서 안의 원본 이미지 파일을 순서대로 ZIP으로 저장합니다.

- 저장 파일명은 현재 문서 제목 기반의 `<제목>-이미지.zip`입니다.
- ZIP 안의 이미지는 문서 등장 순서대로 `001`, `002`, `003`처럼 번호가 붙습니다.
- 이미지는 재인코딩하지 않고 DOCX 내부 `word/media` 파일 바이트를 그대로 복사합니다.
- 2x2 이하의 DOCX placeholder 이미지는 제외합니다.
- DOCX 해석과 ZIP 생성 모두 콘텐츠 스크립트 안에서 처리하며, 문서 내용을 외부로 전송하지 않습니다.

## 단락 스타일 셋팅

Google Docs 패널의 [추가기능] ➝ [단락 스타일 셋팅]은 브릿지와 AI 없이 확장 안에서 동작합니다. 골든래빗 집필 가이드 기준으로 문서의 단락 스타일 정의(일반 텍스트, 제목 1~5)를 자동으로 맞춥니다.

- [전체 셋팅] 또는 스타일별 개별 항목을 선택할 수 있습니다.
- 문서 끝에 임시 문단을 만들어 목표 서식을 입힌 뒤, Docs의 [스타일 업데이트] 메뉴를 자동 실행해 스타일 정의를 갱신하고 임시 문단을 삭제합니다.
- 실행 중 Docs 메뉴가 잠깐씩 열렸다 닫히는 것은 정상입니다. 실행 중에는 문서를 편집하지 마세요.
- 셋팅 값: 일반 텍스트 10pt / 제목 1 25pt 굵게 / 제목 2 16pt 굵게 / 제목 3 14pt 굵게 파랑(#4a86e8) / 제목 4 12pt 굵게 밑줄 파랑(#1155cc) / 제목 5 10pt 굵게(기본 크기 = 일반 텍스트).
- 폰트 패밀리와 줄간격은 건드리지 않습니다. 글자 크기·굵기·기울임 해제·밑줄·색만 설정합니다.
- 스타일 정의를 바꾸므로 해당 스타일을 쓰는 기존 문단 전체에 즉시 반영됩니다.

## 규칙 형식

기본 규칙은 기존처럼 2칸 배열입니다.

```json
["원문", "교정"]
```

문맥 예외가 필요한 경우에만 세 번째 옵션 객체를 붙일 수 있습니다.

```json
["의 수", " 수", { "rejectAfter": ["많"] }]
["끔하", "끔 하", { "rejectBefore": ["깔"] }]
```

현재 지원 옵션:

- `rejectBefore`: 매칭 직전 문자열이 있으면 제외
- `rejectAfter`: 매칭 직후 문자열이 있으면 제외
- `allowCodeToken`: 코드·URL 토큰 판정(가드 B)을 건너뜀

`allowCodeToken`은 경로·명령어·파일명 자체를 고치는 규칙에 씁니다. 엔진은 기본적으로
`~/.claude/skills/foo/`처럼 순수 ASCII에 `/ . _ :`가 섞인 토큰을 코드로 보고 검출하지 않는데,
그 토큰이 바로 교정 대상일 때는 이 플래그로 예외를 둡니다. ASCII 단어 경계(가드 A)와
`rejectBefore`/`rejectAfter`는 그대로 적용됩니다.

```json
["~/.claude/skills/", "skills/", { "allowCodeToken": true }]
```

`rules.json` 정본은 Google Sheets 규칙 시트입니다. 시트를 수정한 뒤 루트에서 다음 명령을 실행합니다.

```bash
python3 tools/sync_rules.py
```

`tools/sync_rules.py`는 시트 C열의 옵션 JSON을 읽고, C열이 비어 있으면 기존 `rules.json`의 같은 룰 옵션을 보존합니다.

## 제한사항

- Google Docs 본문 인라인 밑줄은 제공하지 않습니다.
- 일반 웹페이지에서는 서로 다른 DOM 요소 경계에 걸친 오탈자를 잡지 못합니다.
- 페이지 또는 문서당 표시 한도는 500건입니다.
- 규칙은 문맥 전체를 이해하지 않는 문자열 매칭이므로 거짓 양성이 있을 수 있습니다.
- URL, 코드, 식별자 내부 영문 규칙은 가능한 한 자동 제외합니다.
- 규칙 시트의 순차 치환 전용 규칙 일부는 정상 표기까지 과검출하므로 엔진에서 제외합니다.

## 개인정보

기본 내장 규칙 검사는 외부 서버로 문서 내용을 전송하지 않습니다.

AI 교정 생성, AI 사실 검증, AI 문장 길이 조절은 기본 비활성화되어 있습니다. 사용자가 설정에서 [브릿지/외부 기능 사용]을 켜고 직접 요청했을 때만 브라우저가 `http://127.0.0.1` 로컬 브리지로 요청을 보냅니다. 브리지는 설정된 로컬 CLI(Codex, Claude Code, Grok)를 실행할 수 있습니다. 용어 통일 표는 로컬 브리지 없이 브라우저 확장 안에서 vendored `garu-ko`와 내장 규칙 사전으로 처리합니다. AI 교정은 현재 Google Docs 본문을, 사실 검증은 선택 원문과 앞뒤 문맥을, 문장 길이 조절은 선택 원문과 앞뒤 문맥 및 목표 글자 수를 전달합니다. AI 교정의 fact-check 패스는 웹 검색/웹 페이지 조회 도구를 사용할 수 있습니다. 해당 CLI의 동작 방식에 따라 외부 AI 서비스로 전송될 수 있습니다.
